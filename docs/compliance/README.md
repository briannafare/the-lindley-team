# Compliance Archive — MAP Rule / Reg N (12 CFR 1014)

The FTC/CFPB Mortgage Acts and Practices Advertising Rule requires keeping a copy
of **every commercial communication that advertises mortgage credit terms** — website
copy, emails, SMS, chat scripts, nurture sequences, ad creative — for **24 months from
the last date it was used**, with enough info to show who received it and when.

GHL templates get edited **in place**, which destroys the historical record. So we keep
a dated, versioned archive here in git (GitHub = durable storage **outside GHL**; GHL
account changes or template deletions can't erase it).

## What's archived

- `exports/<YYYY-MM-DD>/` — a dated snapshot of every live GHL workflow's marketing
  message bodies (email subject+HTML, SMS, internal notifications), one `.md` per
  workflow, plus an `INDEX.md`. Generated by `scripts/compliance-export.py`.
- **Website marketing/rate/offer copy** — this repository *is* the dated, versioned
  record. Every material copy change is a git commit with a date and author. A tagged
  release (or monthly `git tag compliance-YYYY-MM`) is a clean monthly full-site
  snapshot if you want explicit markers.

## How it's triggered (the actual process)

**Manual export — run before editing.** GHL has no pre-save export hook, so:

1. **Baseline (done):** `2026-07-14` snapshot committed.
2. **Before editing** any workflow email/SMS/nurture body, or the chat widget's scripted
   responses, run the export FIRST so the prior version is preserved, then make the edit:
   ```bash
   set -a && source "<leadgenjay ghl CLI>/.env" && set +a   # loads GHL_FIREBASE_REFRESH_TOKEN
   python3 scripts/compliance-export.py
   git add docs/compliance && git commit -m "compliance snapshot YYYY-MM-DD"
   ```
3. **Website copy:** commit copy changes normally — the diff + date is the record. For a
   monthly marker: `git tag compliance-$(date +%Y-%m) && git push --tags`.

## Annual check (required)

At least once a year, confirm nothing required is missing from the archive. Over-retention
is fine; under-retention is the violation. **A recurring calendar/GHL-task reminder still
needs to be set** — see the build report (owner: Bri). Suggested: annual, "Verify Lindley
compliance archive is complete (Reg N 24-mo)."
